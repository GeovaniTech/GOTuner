# Android release instructions

## Prerequisites and local configuration

JDK 17, Android SDK platform/build tools 36, accepted SDK licenses, and the repository Gradle wrapper. Keep the matching `androidApp/google-services.json` local/ignored. CI obtains it from the `GOOGLE_SERVICES_JSON` repository secret. Never commit this file, service-account files, a keystore or passwords.

The permanent application ID is `br.com.gotuner`. Version is 1.0.0/code 1; increase code for subsequent uploads, and confirm it is unused before the first upload.

## Signing

This audit did not generate, inspect or replace a production key. Use the upload key you manage for Google Play, or create one securely outside the repository following [Android signing guidance](https://developer.android.com/studio/publish/app-signing). Enroll Play App Signing in Console and retain your upload-key backup and certificate.

Supply all four environment variables from a local secret manager or secure shell session:

- `GOTUNER_KEYSTORE_PATH`: absolute path to your upload keystore.
- `GOTUNER_KEYSTORE_PASSWORD`: store password.
- `GOTUNER_KEY_ALIAS`: upload alias.
- `GOTUNER_KEY_PASSWORD`: key password.

Do not paste passwords into commands committed to the repository or enable shell tracing. Partial signing configuration fails early; absent signing variables deliberately produce an unsigned artifact. This artifact cannot be uploaded as-is.

Also set `GOTUNER_PRIVACY_POLICY_URL` to your real public HTTPS policy URL. Without it, the policy link is absent and the app must not be submitted. Review consent/market requirements before releasing with automatic Firebase collection.

Example signing session in Bash (do not save the password values in a file or shell history):

```sh
export GOTUNER_KEYSTORE_PATH="/absolute/secure/path/to/upload-key.jks"
export GOTUNER_KEY_ALIAS="your-upload-alias"
read -r -s -p "Keystore password: " GOTUNER_KEYSTORE_PASSWORD; echo
read -r -s -p "Key password: " GOTUNER_KEY_PASSWORD; echo
export GOTUNER_KEYSTORE_PASSWORD GOTUNER_KEY_PASSWORD
export GOTUNER_PRIVACY_POLICY_URL="https://your-domain.example/privacy"
```

Replace paths, alias and policy URL with real values. No credentials are provided/generated by this repository. Run the build below in that same session, then `unset GOTUNER_KEYSTORE_PASSWORD GOTUNER_KEY_PASSWORD`.

## Validate and build

```sh
./gradlew --no-daemon --continue \
  :shared:jvmTest :androidApp:testDebugUnitTest \
  :androidApp:lintDebug :androidApp:lintRelease \
  :androidApp:assembleDebug :androidApp:assembleRelease :androidApp:bundleRelease
python3 scripts/check_android_pages.py androidApp/build/outputs/bundle/release/androidApp-release.aab
```

Output: `androidApp/build/outputs/bundle/release/androidApp-release.aab`.
R8 mapping: `androidApp/build/outputs/mapping/release/mapping.txt` (retain securely per release; Crashlytics plugin manages mapping upload during configured release tasks). Resource shrinking is enabled. There are no broad project keep-all rules.

Check the exact generated artifact, not just a prior debug build:

```sh
jarsigner -verify -verbose -certs androidApp/build/outputs/bundle/release/androidApp-release.aab
shasum -a 256 androidApp/build/outputs/bundle/release/androidApp-release.aab
```

Confirm the signer is your upload certificate. “jar is unsigned” means signing was not configured. Validate the AAB with a current official [bundletool](https://developer.android.com/tools/bundletool), generate/install test APKs from the signed bundle or use Play internal testing, and exercise minified runtime behavior. The ELF script verifies static alignment, not runtime behavior on a 16 KB device.

## Device and Play workflow

1. Complete TEST_REPORT.md's manual matrix, including all six strings, denial/revocation, long sessions and interruption routes. Validate the signed optimized build.
2. Publish the policy and finish Data Safety/other declarations. Review Firebase console settings and test release Analytics/Crashlytics delivery on a test device; debug builds now disable collection.
3. In Play Console, use Internal testing > Create release, upload the signed AAB, inspect processing/compatibility warnings, and complete the store listing.
4. Review the pre-launch report and meet account-specific closed testing/production access requirements.
5. Approve country availability, pricing and rollout manually. No automatic upload or publication is configured.
